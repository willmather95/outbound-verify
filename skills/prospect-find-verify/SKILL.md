# Prospect find → verify → site-walk

Script: `scripts/verify.py` + `scripts/dso-config.json` (beside this file). Edit the config, never the script, to change the block list, group-language patterns, or service-proof patterns.

1. **Scope.** Write the niche, target service (e.g. full-arch implants), states/cities in priority order, and batch size. Copy `dso-config.json` into the batch folder and add any chains/groups known for that region.
2. **Find.** Use web search plus the business's own site. Only owner-run businesses that actively market the target service. Only include an email you actually saw printed on their own site. Output CSV with no header: `name,city_state,website_url,email,page_where_email_seen`.
3. **Verify.** `python3 verify.py find.csv verified.csv dso-config.json`. SSL verification is on, so a cert error makes a row REVIEW, not a silent pass. Status:
   - FAIL: email not on site, no MX record, or DSO/chain match. Drop it.
   - REVIEW: group language found (independence unsure), no proof of the target service, or SSL error. A person checks the About/Terms/Privacy pages before the lead moves on.
   - VERIFIED: all checks pass.
4. **Site walk** (VERIFIED + cleared REVIEW rows only). Walk each site like a buyer: home, service page, contact/booking, financing. Record per lead: `independent (yes/no/unsure)`, `service_focus 1-5`, ONE checkable fact about their consult path with its exact URL, any price or health claim quoted word for word, owner name if shown. Don't guess. A blank fact means no email.
4b. **Ad-library trigger** (free, public). Check the Google Ads Transparency Center (adstransparency.google.com) and the Meta Ad Library for the business name. If they run ads for the target service, record the ad text, the platform, and any date shown (Meta shows "Started running on"). A live paid ad is a dated why-now: they already pay for this demand. Quote it, don't guess spend. No ads is a fact too, but not a trigger.
4c. **Site evidence teardown (OPTIONAL).** Use on top leads, or on leads that still have no dated trigger after 4b. Scripts: `scripts/teardown/` (beside this file).
   - **Passive only.** Load public pages, scroll, inspect. Never type into, submit or book through a prospect's form, scheduler or chat. Never call. Never add fake `gclid`/`utm` parameters (they write fake visits into the prospect's ad reports). Anything that needs a submit stays UNKNOWN unless the owner runs a test with us.
   - **Capture:** `node scripts/teardown/capture.mjs <batch>/teardown/raw/<domain> <home URL> <contact/appointment URL> <booking URL>`. This is headless Chrome; it writes a HAR, the rendered DOM and a screenshot per page. If the first pass shows zero analytics requests, rerun with `MOUSE=1` (mouse-move and wheel only, no clicks) to wake scripts deferred until interaction. Also fetch the public GTM container (`googletagmanager.com/gtm.js?id=GTM-…`), the GA4/Ads config (`googletagmanager.com/gtag/js?id=G-…` or `AW-…`) and the Meta pixel config (`connect.facebook.net/signals/config/<pixel id>`).
   - **Parse in code:** `scripts/teardown/analyze_capture.py <out>` lists forms, field labels, iframes, `tel:` numbers, tag IDs and vendors. `scripts/teardown/gtm_tags.py <gtm.js>` lists GTM tags and what fires them. Find call tracking by comparing the raw HTML number with the rendered one and looking for vendor scripts. Dates, counts and string matching stay in code.
   - **Jev (pinned `jev-1.13.0`) answers small yes/no questions only:** `scripts/teardown/host-questions.json` per third-party host (from `jev_items.py`) and `form-questions.json` per form, via a small yes/no labeling model (Jev). Then `scripts/teardown/combine_jev.py <dir>`: the top label at ≥ 0.5 wins, otherwise a human decides. **The code vendor table (`KNOWN`, plus `EXTRA` for hosts the page itself proves) overrides Jev.** Log every disagreement. Jev has missed Meta's own domain, CAPI gateways and session-recorder loaders.
   - **Record** one file per lead, `<batch>/teardown/<domain>.md`, with one row per finding. Cover forms (fields, where they post, redirect), booking vendor, call tracking, every tag ID, and which trackers received form data. Label each row CONFIRMED / INFERRED / UNKNOWN with proof (request URL + field names, script src, DOM snippet or screenshot path) and a re-check step. Keep field names, never values. Output stays in the batch folder.
   - **Trigger rule:** only something with a visible date counts (a dated launch post, a first-seen date for a new tool, a Meta "Started running on" date), checked against the 90-day window in code. A tool with no date is a talking point, not a trigger.
   - **Outreach use:** facts with proof only ("your 'Contact Us' conversion fires when someone opens /contact-us; request attached"). **Never make legal, HIPAA or compliance claims, and never imply wrongdoing.** If privacy comes up: "worth reviewing with your counsel." Nothing goes to a prospect without the user's explicit yes.
5. **Outside review.** A second agent from a different vendor than the builder reviews the list for chains, weak facts, and claims we can't back up. Apply fixes and log them in the batch README.
6. **Hand-off.** Batch README: counts by state, top 3 with reasons, open caveats (unsure count, rows without service proof), and sources for any stats. The leads then go to `situation-cold-email`. Sending needs the user's explicit yes.

Rules: keep lead data (names, emails, facts) in the batch folder only, never in this skill or shared notes. Re-run verify within 7 days of sending, since emails and pages change.
